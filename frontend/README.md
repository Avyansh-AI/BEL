# BEL — official React interface

This frontend integrates the supplied `bel-interface-source.zip` with BEL's existing Python backend. The supplied CSS orb, dark palette, typography and Framer Motion animations are preserved. DM Sans and Manrope are bundled locally under the SIL Open Font License; ordinary use makes no font/CDN requests.

## Build and launch

Use Node 22.18 or newer (Node 26.8.1 was tested) and npm:

```powershell
npm ci --ignore-scripts
npm test
npm run build
```

Start BEL using its Python or Windows desktop launcher. The backend serves this compiled `dist/` on its authenticated loopback origin. Open the launch URL generated by BEL; a plain preview URL does not establish an owner session. `npm run dev` and `npm run preview` bind only to `127.0.0.1` and are for interface development, without an API proxy or a simulated conversation mode.

## Integrated behavior

- Typed chat uses `/api/bel/chat` and a 135-second deadline. It is never automatically replayed after a timeout.
- The local launcher supplies a one-time bootstrap value in a URL fragment. It is removed before claiming the owner cookie. The CSRF value stays in memory; WebSocket connections use one-use tickets.
- HTTP requests and `/ws/app` use the same origin. There is no configurable remote control URL in this frontend.
- Up to 200 redacted conversation messages are read from the backend journal; appearance preferences alone are saved in browser storage.
- Settings exposes provider policies, persistent memory corrections/deletion, diagnostics, registered tools and verified file undo. Changes require a server-generated preview and an explicit **Approve once** click. Cancelled and expired previews do not execute.
- Provider editing retains existing quota caps and only permits free use. The selected local model remains the first choice; this frontend does not replace it or store API keys.
- Compact mode works in the browser. The Windows host adds actual tray/background/window lifecycle through `window.pywebview.api.status`, `set_mode` and `close_app`. These methods grant no tool authority. Native-only buttons remain unavailable in a normal browser.
- Speech output requires reviewing local `speech.render`, followed by an explicit **Play audio** click. Speaking animation follows actual playback and Stop interrupts playback.
- Push-to-talk stays disabled unless the backend reports a configured local recognizer. Its capture implementation requires explicit session consent, emits bounded mono 16 kHz WAV, closes tracks on release/cancel/device changes and never calls browser cloud speech recognition.
- BEL wake detection remains unavailable without a valid trained BEL model and owner consent. No wake event, spoken answer or offline response is simulated.

## Tests

`npm test` exercises transport isolation, overlapping React StrictMode session claims, exact approval arguments, deadlines without replay, event/history validation, native bridge readiness, WAV encoding and microphone permission/cancellation races. Device tests use controlled browser API fixtures and do not claim microphone hardware acceptance.

The real Chromium/HTTP/WebSocket integration harness uses temporary synthetic data:

```powershell
..\sight\.venv\Scripts\python.exe tests/live_ui.py
```

It checks owner bootstrap, built-in backend chat, persistent history, reviewed memory and file operations, undo, provider inspection, desktop/compact/mobile layout, disabled unconfigured microphone and absence of external network calls. It writes timestamped results and screenshots under `test-results/`. This harness does not prove model reasoning, native tray operation or physical microphone/audio playback; those belong to separate backend/Windows acceptance tests.

## Source boundaries

`SOURCE_BASELINE.json` identifies the supplied archive. `src/components/Orb.tsx` and the main visual CSS retain its orb design. Transport lives in `src/lib/belApi.ts`, optional local capture in `src/lib/voice.ts`, and native readiness checks in `src/lib/native.ts`. Tool proposals remain untrusted until the backend validates them and the owner grants the exact action.
