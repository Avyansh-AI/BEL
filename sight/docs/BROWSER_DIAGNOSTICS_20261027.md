## Failure and repair

The [original fresh-environment check](../../audit-tests/20261024-security/final-dependencies/offline-runtime.log) failed with `Page.captureScreenshot: Unable to capture screenshot`. Two unchanged fresh-process rechecks later passed. Failure-time RAM/commit counters were unavailable, so subsequent memory pressure observations do not prove that memory exhaustion caused the failure.

The concrete diagnostic defect was reproducible: the fixed child worker reduced errors to an exception class, and the parent rejected a nonzero exit before parsing the bounded response. Consequently, useful failure categories never reached SIGHT's owner-local audit record. New child-process tests first demonstrated the missing behavior, then passed after repair.

## Browser evidence and resource limits

The final browser batch used Playwright **1.64.0** and Chromium **156.0.8078.4**. Browser operation latency ranged from **0.578 to 0.641 seconds**, averaging **0.6131 seconds**. Available host RAM immediately before capture ranged from **2,066.13 to 2,404.90 MiB**. These are shared-host measurements during this serial batch, not isolated SIGHT allocations or an artificial low-memory stress test.

All captures produced nonblank **1024×768** PNGs, and all cases retained disabled network, scripts and submission. Successful ordinary captures leave the historical intermittent failure unresolved.

Native-component security remains a separate limitation. Google's [20 October stable release](https://chromereleases.googleblog.com/2026/10/stable-channel-update-for-desktop_02018666648.html) is newer than the measured browser and includes security fixes. Playwright [1.64.1 release notes](https://github.com/microsoft/playwright/releases/tag/v1.64.1) describe other fixes, while its [browser manifest](https://github.com/microsoft/playwright/blob/v1.64.1/packages/playwright-core/browsers.json) still selects Chromium 156.0.8078.4. Upgrading that Python package alone therefore does not establish a native-browser security update or screenshot fix. Exact applicability of the newer Chromium fixes to this constrained adapter has not been certified; sandboxing and offline policy do not replace component advisory review. These sources were checked again on 27 October; no dependency or runtime was changed during the soak.

Upstream code narrows the meaning of the error: Chromium emits this exact failure when its returned screenshot image is empty, and its surface-copy path already has internal retry handling. Playwright already waits for fonts before screenshot capture. This supports retaining the original timeouts and sandbox settings; it does not identify why the image was empty on this host. Primary sources: [Chromium screenshot result handling](https://github.com/chromium/chromium/blob/156.0.8078.4/content/browser/devtools/protocol/page_handler.cc#L1860), [Chromium surface copy](https://github.com/chromium/chromium/blob/156.0.8078.4/content/browser/renderer_host/render_widget_host_impl.cc#L3736), [Playwright screenshot handling](https://github.com/microsoft/playwright/blob/v1.64.0/packages/playwright-core/src/server/screenshotter.ts).
